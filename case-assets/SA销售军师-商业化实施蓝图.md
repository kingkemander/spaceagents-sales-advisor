# SA 销售军师｜商业化实施蓝图

## 1. 产品定位

SA 销售军师是一套面向长周期顾问式销售的“客户记忆与行动系统”。它不替销售自动发消息，而是把分散材料转化为持续更新的客户记忆，主动发现资料缺口和跟进节点，并结合专业销售方法与销售本人的表达习惯，给出每天可执行的建议。

适用场景：房产、汽车、写字楼、产业园区、企业服务、招商、工程项目等高客单、长周期、多人决策的销售业务。

## 2. 商业化标准架构

### 2.1 三类输入

1. **客户材料**：聊天截图、长截图、会议纪要、录音转写、PDF、Word、表格、报价与项目方案。
2. **企业知识**：项目事实、产品边界、价格政策、常见异议、合法使用的培训资料、脱敏成交案例。
3. **销售个人样本**：销售本人发出的聊天内容、可区分说话人的会议表达、本人主动修改过的回复。

### 2.2 七步业务主流程

1. **一客一档**：按客户建立专属文件夹，原始材料只追加、不覆盖。
2. **理解与索引**：图片和长截图优先使用视觉模型理解；普通文档转 Markdown；所有产物记录来源、时间与哈希。
3. **统一确认**：销售确认客户归属、关键事实、冲突、敏感信息与写入范围。
4. **动态客户记忆**：更新身份、需求、阶段、顾虑、决策链、项目节点、下一步和时间线。
5. **资料缺口发现**：计算资料完整度，输出缺失字段和下一次最自然的补问建议。
6. **今日行动排序**：依据承诺到期、跟进日期、沉默周期、风险和证据强度生成优先级。
7. **策略与回复**：先核对事实，再分析客户决策，最后按销售个人表达卡生成可复制回复；执行结果回流客户记忆。

### 2.3 两个持续增长闭环

#### 客户记忆闭环

`新材料与反馈 → 事实/状态更新 → 资料补问与行动建议 → 沟通结果回流 → 更新时间线`

验收要求：不重复要求上传旧材料；新信息必须进入正确客户；历史事实可追溯；冲突不静默覆盖。

#### 个人表达成长闭环

`本人样本 → 表达卡片 → 按本人风格生成 → 本人校正 → 更新偏好与成熟度`

表达卡至少包含：

- 整体气质；
- 常用称呼；
- 句长与消息分段；
- 常用开场、推进和收尾方式；
- 面对异议时的表达习惯；
- 禁止表达和不符合本人的措辞；
- 样本数量、最近更新时间、画像成熟度。

学习边界：只有销售明确提供或确认的本人表达才能计入口吻资料库；不能把客户说的话误学成销售口吻。

## 3. 客户资料完整度标准

### 3.1 建议字段

- 来源渠道；
- 姓名与联系方式；
- 公司全称；
- 职位与角色；
- 所属行业；
- 核心需求；
- 预算范围；
- 项目周期；
- 决策关系；
- 当前阶段；
- 下一次跟进时间。

### 3.2 展示规则

作战台不只显示“缺少公司信息”，还应同时呈现：

1. 当前资料完整度；
2. 最重要的 3–4 个缺口；
3. 为什么这些信息会影响推进；
4. 下次沟通中最自然的一句补问；
5. 已确认的信息不重复追问。

示例：抖音主页线索只有电话时，不要求销售一次问完全部资料。系统可先建议：“您这次主要是自己使用，还是代表公司在了解？我好按实际用途给您准备资料。”

## 4. 专业销售判断结构

每次给出回复或推进建议时，固定按照以下顺序：

1. **企业事实**：价格、政策、库存、交付和承诺边界；
2. **客户事实**：客户原话、最近状态、历史时间线和已确认资料；
3. **客户决策判断**：需求是否清晰、信任是否建立、决策链是否完整、是否害怕选错；
4. **方法选择**：只选 1–2 个与场景相关的方法框架；
5. **行动设计**：本次沟通唯一目标、应提供的证据、希望客户完成的下一步；
6. **个人表达改写**：按销售本人的称呼、句长、节奏与边界形成最终话术。

推荐方法库包括：SPIN Selling、The Challenger Sale、The Trusted Advisor、The JOLT Effect、Getting to Yes、Strategic Selling、Gap Selling，以及企业合法拥有的内部方法和脱敏案例。

## 5. 作战台产品信息架构

### 今日行动

- 今日优先客户；
- 为什么现在跟；
- 本次唯一目标；
- 下一步动作；
- 风险与证据；
- 可复制回复。

### 客户资料

- 客户卡片；
- 最新状态；
- 资料完整度；
- 资料待补；
- 下一句补问；
- 历史时间线。

### 个人表达

- 表达画像成熟度；
- 已学习的聊天/会议样本数量；
- 整体气质与语言特征；
- 称呼、节奏、跟进与异议习惯；
- 禁止表达；
- 下一步建议补充的样本类型。

### 成长建议

- 与当前真实客户相关的一个思考角度；
- 一个可以尝试的销售动作；
- 一个值得复盘的问题；
- 可选的延伸阅读链接。

成长建议是可选启发，不设置强制学习、考试或打卡。

## 7. 技能协同标准

| 能力 | 输入 | 核心处理 | 输出 |
|---|---|---|---|
| 材料入库 | 客户文件夹 | 识别、转写、索引、确认 | 可追溯材料记录 |
| 客户记忆 | 已确认新事实 | 合并、冲突检查、时间线 | 客户卡与最新状态 |
| 个人表达 | 本人表达样本 | 风格提炼、反馈更新 | `sales-soul.md` |
| 每日跟进 | 客户索引与节点 | 优先级、缺口、风险 | HTML 销售作战台 |
| 回复起草 | 客户状态与目标 | 事实核对、决策分析、口吻改写 | 三类可复制回复 |
| 销售成长 | 实际沟通结果 | 行为复盘、方法映射 | 可选成长建议 |

## 8. 行业复制步骤

1. 明确行业销售周期、客户阶段与核心资料类型；
2. 定义客户资料完整度字段和跟进优先级规则；
3. 导入企业事实、产品边界、常见异议和脱敏案例；
4. 配置客户文件夹与索引结构；
5. 采集 20–50 条销售本人有效表达，建立初始表达卡；
6. 用 3 个典型客户完成端到端试跑；
7. 按“事实正确、归属正确、提醒有效、回复像本人、页面可读”五项验收；
8. 设置每日作战台生成任务，再逐步扩大客户范围。

## 9. 商业化验收清单

- [ ] 能一次处理同一客户文件夹中的多类材料；
- [ ] 图片、长截图和文档均有稳定识别路径与降级方案；
- [ ] 客户归属和正式写入前有统一确认；
- [ ] 新材料不会传错客户，历史记录不被覆盖；
- [ ] 客户卡能展示资料完整度、主要缺口和自然补问；
- [ ] 作战台能回答“今天跟谁、为什么跟、做什么、有什么风险”；
- [ ] 回复引用已确认事实，不虚构价格、库存或承诺；
- [ ] 个人表达资料库能随本人反馈持续更新；
- [ ] 面向销售的页面不出现模型、OCR、文件路径或内部处理措辞；
- [ ] 不连接 CRM/聊天平台，不自动向客户发送信息；
- [ ] Windows 与 macOS 均可安装，运行时依赖和失败提示清晰；
- [ ] 覆盖升级不删除客户工作区和历史资料。

## 10. 标准演示脚本

1. 展示一个只含电话、来源为抖音主页的新线索，说明系统会主动标记资料待补；
2. 把聊天截图、会议纪要和项目文件放进该客户文件夹；
3. 展示材料理解结果和统一确认卡；
4. 确认后展示客户卡、资料完整度和时间线的变化；
5. 打开作战台，展示今天为什么要跟、下一句如何自然补问；
6. 展示“个人表达”页面，说明系统如何积累销售口吻；
7. 用同一客户分别生成通用回复和本人风格回复，展示差异；
8. 最后展示沟通结果回流后，客户记忆与表达画像如何继续增长。

## 11. 产品边界

- 不连接 CRM、微信或企微；
- 不自动发送消息；
- 未经销售确认，不写入正式客户档案；
- 不把推测当作客户事实；
- 不虚构价格、优惠、库存、交付和他人承诺；
- 不把受版权保护的销售书籍全文打包进插件，只保存原创方法卡、用户合法资料和公开链接；
- 客户原始材料保存在企业自己的本地工作区。
