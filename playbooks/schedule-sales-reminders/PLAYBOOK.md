# 销售提醒与排期

## 识别提醒类型

根据用户原话选择最小任务类型：

1. **一次性行动提醒**：在指定时间提醒完成一项销售动作。
2. **到点完成确认**：到点给出任务内容并询问“完成了吗”。
3. **每日固定语音提醒**：每天到点播放一项明确行动。
4. **每周固定语音提醒**：每周到点提醒销售进行复盘或处理固定事项。
5. **半年客户推进计划**：生成未来六个月的阶段安排，只为关键节点创建自动提醒。

提醒创建前的行动选择可参考 [references/automation-prompts.md](references/automation-prompts.md)，但不得把长提示词原样写入语音提醒。

## 创建规则

1. 用户明确说“提醒我”“每天告诉我”“到时候问我”即视为创建授权，不再重复确认。
2. 从用户原话提取时间、时区、重复规则、客户和动作。使用当前本地时区；创建前把相对时间解析为明确日期时间。
3. 仅在时间确实无法判断、指定时间已经过去且无法确定用户指今天还是明天、或缺少必要客户/事项时，询问一个最小问题。
4. 当前对话先生成音频文件，再调用系统调度器创建本机提醒；不要打开设置页，不要创建 SpaceAgents 自动任务，不要用网页模拟点击。创建成功后返回提醒名称、首次触发时间、音频文件已生成和播报次数。
5. 创建前检查相同标题、客户、时间和重复规则的任务；已有相同任务时更新，不重复创建。
6. 所有提醒默认只播放语音，不弹桌面横幅、通知栏气泡或任务栏弹窗。
7. 只有用户明确说“在 SpaceAgents 对话里提醒我”时才传 `--delivery spaceagents`；其他情况一律使用默认的 `system`。

## 对话内直接创建

先结合当前客户资料把提醒压缩为不超过 300 个汉字的一句话，写入当前工作区临时 Markdown 文件，再执行：

```bash
python3 "<运行时根目录>/sa_sales_advisor/cli.py" automation create \
  --workspace "<当前 SpaceAgents 工作区>" \
  --name "<简短任务名称>" \
  --prompt-file "<提醒提示词文件>" \
  --schedule "<once|daily|weekly>" \
  --time "<HH:MM>" \
  --date "<一次性提醒的 YYYY-MM-DD，可选>" \
  --delivery system \
  --repeat 3
```

- `--workspace` 必须传当前 SpaceAgents 项目根目录，不能传 `SA销售工作区` 子目录。
- 命令输出 `status: created-system-reminder`，并包含 `trigger_at`、`audio_pre_generated: true` 和 `voice: true` 才算创建成功。
- `once` 播报完成后自动删除系统任务；`daily` 和 `weekly` 保留并按固定周期触发。
- 用户说“查看我的提醒”时运行 `automation list --workspace "<工作区>"`，默认读取本机提醒索引。
- 创建过程发生在当前对话；到点不运行模型、不读取客户档案、不向任何 SpaceAgents 对话发消息。

- macOS：创建时用系统语音生成独立 AIFF 音频；`launchd` 到点用 `afplay` 直接播放 1–5 次，随后卸载任务并删除一次性音频。
- Windows：创建时用系统语音生成独立 WAV 音频；任务计划程序到点用 `SoundPlayer` 直接播放 1–5 次，随后删除一次性任务、脚本和音频。
- 提醒内容应是短句，例如“给吴总发送看楼时间确认，这件事完成了吗？”；不要把整份客户档案或内部操作提示词拿去播报。
- 不生成视频。音频播报比启动视频播放器更快，也不会受到默认播放器、窗口焦点和视频编码影响。
- 电脑睡眠时系统任务可能在唤醒后补执行，但插件不承诺强制唤醒电脑或在关机状态准点响。
## 创建时确定提醒内容

本机提醒到点时不会再调用 AI，因此必须在创建时确定最终文字。提醒只包含“对象 + 唯一动作 + 完成确认”，例如：

```text
该给吴总发送看楼时间确认了，这件事完成了吗？
```

不要在语音里播报客户长画像、风险分析、建议话术或多个客户。需要这些内容时，在创建提醒的当前对话里正常展示，语音闹钟只保留最关键的一件事。

## 每日文字行动清单

每次最多列出 5 位真正需要行动的客户，按时间顺序输出：

```text
【今日销售行动｜YYYY-MM-DD】

09:30｜客户名
要做：本次唯一动作
原因：为什么必须现在做
建议发送：一条可直接复制的消息

15:00｜客户名
要做：本次唯一动作
原因：为什么必须现在做
建议发送：一条可直接复制的消息

今天最重要的一件事：……
```

没有事实依据时不强行安排联系；改为提示补资料、内部准备或暂缓。绝不自动向客户发送消息。

## 播放后的完成确认

音频本身必须直接包含对象、行动和完成提问，例如：“该给吴总发送看楼时间确认了，这件事完成了吗？”到点只播放音频，不打开 SpaceAgents、不生成长报告。

用户之后回到任意销售军师对话并回复“已完成”时，只有明确关联客户且用户同意写入时，才把完成结果更新进客户时间线；否则只结束或更新该提醒。

无论是否写入客户时间线，都要把已完成事项记录到本地任务事件流水，供每天 18:00 私人知识库同步使用：

```bash
python3 "<运行时根目录>/sa_sales_advisor/cli.py" activity add \
  --root "<当前项目>/SA销售工作区" \
  --event-type "completed" \
  --title "<已完成事项>" \
  --customer-id "<可选客户 ID>" \
  --customer-name "<可选客户名>" \
  --details "<完成结果>"
```

## 半年推进计划

1. 从已确认的客户周期、承诺、交付、预算和决策节点生成未来六个月安排。
2. 保存到 `SA销售工作区/plans/sales-plan-<YYYY-MM-DD>.md`。
3. 按“本周、未来 30 天、第 2–3 个月、第 4–6 个月”组织；每个阶段包含目标、关键客户、准备材料、触发条件和退出条件。
4. 不虚构客户日期。没有明确日期时写成条件触发，例如“客户确认预算后 2 个工作日内提交方案”。
5. 默认只创建一个每日简报和必要的一次性关键节点提醒；不要为半年中的每一天创建任务。只有用户明确要求时才增加每周或每月复盘。

## 固定边界

- 自动提醒销售本人，不自动联系客户。
- 不自动发送微信、短信、邮件或企业微信消息。
- 不把未经确认的价格、库存、交付和优惠写进建议消息。
- 不用“系统分析”“AI判断”“读取文件”等内部措辞；提醒只呈现清晰的销售行动。
