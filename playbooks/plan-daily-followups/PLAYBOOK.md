# 每日跟进军师

## 生成作战台

1. 读取所有 `customers/*/customer.json`，不读取工作区外文件。
2. 优先级依次考虑：已逾期承诺、今天到期、未来两天到期、明确客户活跃信号、长时间无进展、资料缺失和过度打扰风险。
3. 不为没有事实依据的客户生成强行催单建议。
4. 为每个入选客户给出：今天是否该跟、原因、下一步、风险、回复草稿、资料完整度和最适合补问的一项信息。
   资料缺口优先检查来源渠道、公司全称、客户职位、所属行业、核心需求、预算、项目周期和决策关系。补问应自然融入下一次沟通，不要像审问或一次索取全部资料。
   页面只显示面向销售的业务结论。证据用于内部校验，不在卡片上展示文件路径、客户 ID、模型、AI、OCR、识图、入库、置信度或其他处理痕迹。
5. 必要时读取 `<运行时根目录>/playbooks/draft-sales-reply/PLAYBOOK.md` 补充草稿，并保持人工发送边界。
6. 运行：

```bash
python3 "<运行时根目录>/sa_sales_advisor/cli.py" dashboard --workspace "<当前项目>/SA销售工作区"
```

7. 返回一条不超过 120 字的提醒，再给出 `dashboard/index.html` 的可点击路径。

排序逻辑见 [references/followup-priority.md](references/followup-priority.md)。页面交互来自 [assets/dashboard-template.html](assets/dashboard-template.html)。

## 设置自动任务

首次设置时只询问提醒时间和是否排除周末。推荐工作日上午 8:45，但不得未经确认创建。

如果当前环境提供自动任务能力，在用户确认后创建每日任务，提示词应明确：读取当前项目的 `SA销售工作区`、运行本 Skill、更新 HTML、只报告需要行动的客户；不要连接外部平台或发送消息。

如果自动任务能力不可用，给出手动设置步骤，不伪装创建成功。

## 通知格式

`今日共 N 位客户需要处理：A 位必须、B 位建议、C 位存在风险。优先处理：客户名——原因。打开销售作战台查看详情。`
