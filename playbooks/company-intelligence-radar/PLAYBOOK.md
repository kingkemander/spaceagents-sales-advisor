# 客户企业动态雷达

## 执行顺序

1. 从客户档案和已确认材料中提取企业法定全称、统一社会信用代码、注册地区、曾用名、品牌和关联公司；不确定时只展示待确认项。
2. 使用 `company-radar register` 保存当前客户的企业身份。法定全称和统一社会信用代码都缺失时停止正式核验，只能收集待核验线索。
3. 使用 `company-radar plan` 生成本次查询计划，覆盖招投标、项目建设、经营变化、资本动态、招聘、司法风险、知识产权和官方新闻。每家企业每轮最多纳入 100 条候选结果；100 条以内符合范围的候选全部核验，超出时优先最新、官方和高业务相关性结果。
4. 优先使用当前环境已有的联网搜索、浏览器或网页读取工具执行查询；先查官方原始来源，再查企业官网和权威媒体，最后使用搜索引擎补漏。
5. 每个结果必须打开原文核对企业主体、企业角色、发布日期、项目、金额和地区。验证码、登录、403、429 或禁止自动访问时停止，不尝试绕过；把链接保存为待核验线索。
6. 把结果整理为 [references/evidence-schema.md](references/evidence-schema.md) 规定的 JSON，使用 `company-radar import` 写入独立证据流水。
7. 向销售展示“已核验动态”和“待核验线索”两个区。外部动态不自动改变客户阶段、金额、态度或承诺。
8. 销售确认某条动态与当前机会相关后，使用 `company-radar confirm` 写入客户企业动态与时间线，再读取回复 Playbook 生成自然的跟进切入点。待核验线索不得进入正式客户事实。

## 命令

```bash
python3 "<运行时根目录>/sa_sales_advisor/cli.py" company-radar register \
  --workspace "<销售数据>" --customer-id "<客户ID>" \
  --legal-name "<企业法定全称>" --credit-code "<统一社会信用代码，可选>" \
  --region "<注册地区，可选>"

python3 "<运行时根目录>/sa_sales_advisor/cli.py" company-radar plan \
  --workspace "<销售数据>" --customer-id "<客户ID>"

python3 "<运行时根目录>/sa_sales_advisor/cli.py" company-radar import \
  --workspace "<销售数据>" --customer-id "<客户ID>" \
  --input-file "<结构化结果JSON>"

python3 "<运行时根目录>/sa_sales_advisor/cli.py" company-radar confirm \
  --workspace "<销售数据>" --customer-id "<客户ID>" \
  --evidence-id "<已核验证据ID>"
```

## 面向销售的输出

每条动态只呈现日期、事件、企业角色、可能影响、待确认信息、一个低压力跟进切入点和原文入口。不要展示“爬虫、模型、置信度、抓取失败、内部路径”等技术措辞。内部的 `verified` 对外显示为“来源已核验”，`pending` 对外显示为“信息待确认”。

## 固定边界

- 搜索摘要不是事实；无法访问原文时不得标记为已核验。
- 同名企业不得仅凭简称合并；统一社会信用代码冲突时直接拒绝归属。
- 不绕过验证码、登录、封禁、访问频率限制或网站条款。
- 不向客户自动发送消息，不替销售公开评论企业风险。
- 电脑关机时本地插件不承诺持续监控；真正 24 小时监控需要独立云端服务。
